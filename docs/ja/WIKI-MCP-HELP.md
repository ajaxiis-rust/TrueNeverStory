# Wikipedia RAG — ユーザーガイド

Wikipedia RAG（Retrieval-Augmented Generation）は、Wikipediaの実際の知識でゲームワールドを自動的に強化します。ワールドを作成すると、システムは関連するトピックを調査し、エージェントが正確で詳細なナラティブに使用する知識ベースを構築します。

## 仕組み

### 自動調査

ワールド作成時、システムは以下の処理を行います：

1. **キーワードを抽出** — ワールドの説明から（例：「中世」「騎士」「イングランド」）
2. **Wikipediaを検索** — 関連記事を探す
3. **記事をパース** — テキスト、セクション、カテゴリを抽出
4. **チャンクに分割** — 約500トークンのチャンクにオーバーラップ付きで分割
5. **RAGインデックスを構築** — エージェントのクエリ用にチャンクを保存

### シナリオ例

文学的な参照（アイヴァンhoe、クエンティン・ダード）付きの**中世騎士**のワールドが欲しい場合：

```
ユーザー：「騎士と中世のワールドが欲しい」
```

システムが自動的に調査：
- **地理** — 中世イングランドの城、都市、交易路
- **日常生活** — 食べ物、衣服、工芸、社会構造
- **武器と防具** — 剣、盾、チェインメイル、プレートアーマー
- **統治者と指揮官** — 王、領主、その性格と日付
- **災害** — その時代のペスト、火災、地震

これらの知識はすべてRAGインデックスに保存され、エージェントが正確で詳細なナラティブを生成するために使用します。

### アイドル時の強化

プレイヤーが1時間以上非アクティブの場合、システムはバックグラウンドで調査を継続：
- ワールドに関連するトピックを調査
- RAGインデックスに詳細を追加
- 次のエージェント応答が新しい知識を使用

## 進捗追跡

### Web UI

リアルタイムの進捗はSSE（Server-Sent Events）で利用可能：

```
GET /api/wiki/research/{worldId}/progress
```

進捗段階：
1. **ワールド生成** — LLMがワールドフレームを作成
2. **Wikipedia調査** — 記事のダウンロードとパース
3. **RAG構築** — ベクトルインデックスの作成

### CLI進捗

ワールド作成中のターミナル進捗バー：

```
[ステージ 2/3: Wikipedia調査] 中世の騎士道を調査中...
  [▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓] 50% (15/30)
  → 現在：騎士
  → エラー：1（スキップ：イングランドの城）
```

### チャットボタン

Web UIで調査を制御：
- **🌍 Wikipediaを調査** — 調査を開始
- **⏸ 一時停止** — 調査を一時停止
- **▶ 再開** — 調査を再開

## APIエンドポイント

| メソッド | パス | 説明 |
|---------|------|------|
| `GET` | `/api/wiki/research/{worldId}/progress` | SSE進捗ストリーム |
| `POST` | `/api/wiki/research/{worldId}` | 調査を開始 |
| `POST` | `/api/wiki/research/{worldId}/pause` | 調査を一時停止 |
| `POST` | `/api/wiki/research/{worldId}/resume` | 調査を再開 |
| `GET` | `/api/wiki/research/{worldId}/status` | 現在のステータスを取得 |

## MCP統合

Wikipedia RAGはエージェント用のMCPツールとして利用可能：

### Wiki Search Tool

```typescript
// 関連知識を検索
const results = await wikiSearch({
  query: "中世の騎士道",
  worldId: "my-world",
  limit: 10
});
```

戻り値：
```json
[
  {
    "article": "騎士",
    "section": "歴史",
    "text": "騎士道の概念は中世に起源を持ちます...",
    "score": 0.85
  }
]
```

### エージェントでの使用

エージェントは応答生成時に自動的にRAGを使用：
- **劇作家** — ナラティブパターンに歴史的コンテキストを使用
- **バリデーター** — Wikipediaデータに対して事実を検証
- **スタイリスト** — 実際の詳細で説明を強化
- **アクター** — ワールドに関する正確なNPC知識を提供

## 設定

### リトライポリシー

- **記事あたり5回**の試行
- **試行あたり2分**のタイムアウト
- **指数バックオフ**：5秒 → 10秒 → 20秒 → 40秒 → 80秒

### グレースフルデグラデーション

Wikipediaが利用できない場合：
- ワールド作成はWikipediaデータなしで継続
- エージェントはLLMが生成した知識のみを使用
- バックグラウンドで調査をリトライ

## トラブルシューティング

| 問題 | 解決策 |
|------|--------|
| 調査が開始されない | Wikipedia APIのアクセシビリティを確認 |
| 進捗が止まる | システムタブ → 操作ログを確認 |
| 記事が読み込まれない | リトライポリシーが一時的な障害を処理 |
| RAGがエージェントに使用されない | `enableWikipediaResearch()`が呼び出されたことを確認 |
| "認証が必要" | envまたは設定で`AUTH_PASSWORD`を設定 |

## 技術詳細

### チャンク戦略

記事は約1500文字（約500トークン）のチャンクに分割：
- **オーバーラップ**：チャンク間150文字
- **セクション**：各セクションは独立してチャンク化
- **メタデータ**：各チャンクは記事タイトル、セクション、カテゴリを保存

### 検索アルゴリズム

Wiki検索ツールはキーワードマッチングを使用：
1. クエリを単語に分割
2. 各チャンクで単語の存在を確認
3. 関連性スコアを計算（一致数 / 総単語数）
4. スコアでソートされた上位結果を返す

### ストレージ

- **SQLite**：記事メタデータとチャンクテキスト
- **FAISS**：セマンティック検索用ベクトル埋め込み
- **ワールドごとの分離**：各ワールドは独自のRAGインデックスを持つ
