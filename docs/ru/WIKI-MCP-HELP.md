# Wikipedia RAG — Руководство пользователя

Wikipedia RAG (Retrieval-Augmented Generation) автоматически обогащает игровые миры реальными знаниями из Wikipedia. При создании мира система исследует relevant темы и создаёт базу знаний, которую агенты используют для точных и подробных нарративов.

## Как это работает

### Автоматическое исследование

При создании мира система:

1. **Извлекает ключевые слова** из описания мира (например, "средневековье", "рыцари", "Англия")
2. **Ищет в Wikipedia** relevant статьи
3. **Парсит статьи** — извлекает текст, секции, категории
4. **Разбивает на чанки** — делит на куски по ~500 токенов с перекрытием
5. **Создаёт RAG индекс** — сохраняет чанки для запросов агентов

### Пример сценария

Вы хотите мир **средневековых рыцарей** с литературными отсылками (Айвенго, Квентин Дорвард):

```
Пользователь: "Хочу мир рыцарей и средневековья"
```

Система автоматически исследует:
- **География** — замки, города, торговые пути в средневековой Англии
- **Быт** — еда, одежда, ремёсла, социальная структура
- **Оружие и доспехи** — мечи, щиты, кольчуга, латные доспехи
- **Правители и полководцы** — короли, лорды, их характеры и даты
- **Катаклизмы** — чумы, пожары, землетрясения эпохи

Все эти знания сохраняются в RAG индексе и используются агентами для генерации точных, подробных нарративов.

### Обогащение в простое

Когда игрок неактивен более 1 часа, система продолжает исследование в фоне:
- Исследует темы, связанные с миром
- Добавляет больше деталей в RAG индекс
- Следующие ответы агентов используют новые знания

## Отслеживание прогресса

### Веб-UI

Прогресс в реальном времени доступен через SSE (Server-Sent Events):

```
GET /api/wiki/research/{worldId}/progress
```

Этапы прогресса:
1. **Генерация мира** — LLM создаёт каркас мира
2. **Wikipedia исследование** — Загрузка и парсинг статей
3. **Создание RAG** — Создание векторного индекса

### CLI прогресс

Прогресс-бар в терминале при создании мира:

```
[Этап 2/3: Wikipedia исследование] Исследую средневековое рыцарство...
  [▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓] 50% (15/30)
  → Текущая: Рыцарь
  → Ошибки: 1 (пропущено: Замки_в_Англии)
```

### Кнопки в чате

В веб-UI вы можете управлять исследованием:
- **🌍 Исследовать Wikipedia** — Начать исследование
- **⏸ Пауза** — Приостановить исследование
- **▶ Продолжить** — Возобновить исследование

## API Endpoints

| Метод | Путь | Описание |
|-------|------|----------|
| `GET` | `/api/wiki/research/{worldId}/progress` | SSE поток прогресса |
| `POST` | `/api/wiki/research/{worldId}` | Начать исследование |
| `POST` | `/api/wiki/research/{worldId}/pause` | Приостановить исследование |
| `POST` | `/api/wiki/research/{worldId}/resume` | Возобновить исследование |
| `GET` | `/api/wiki/research/{worldId}/status` | Получить текущий статус |

Wikipedia RAG доступен как MCP инструмент для агентов:

### Wiki Search Tool

```typescript

  query: "средневековое рыцарство",
  worldId: "my-world",
```

### Использование в агентах

Агенты автоматически используют RAG при генерации ответов:
- **Драматург** — Использует исторический контекст для нарративных паттернов
- **Валидатор** — Проверяет факты по данным Wikipedia
- **Стилист** — Обогащает описания реальными деталями
- **Актёр** — Обеспечивает точные знания NPC о мире

## Конфигурация

### Политика повторов

- **5 попыток** на статью
- **2 минуты таймаут** на попытку
- **Экспоненциальная задержка**: 5с → 10с → 20с → 40с → 80с

### Graceful degradation

Если Wikipedia недоступен:
- Создание мира продолжается без данных Wikipedia
- Агенты используют только знания, сгенерированные LLM
- Повторные попытки исследования в фоне

## Решение проблем

| Проблема | Решение |
|----------|---------|
| Исследование не начинается | Проверьте доступность Wikipedia API |
| Прогресс завис | Проверьте вкладку Система → Логи операций |
| Статьи не загружаются | Политика повторов обрабатывает временные сбои |
| RAG не используется агентами | Убедитесь, что `enableWikipediaResearch()` был вызван |
| "Требуется аутентификация" | Установите `AUTH_PASSWORD` в env или Настройках |

## Технические детали

### Стратегия чанкинга

Статьи разбиваются на чанки по ~1500 символов (~500 токенов):
- **Перекрытие**: 150 символов между чанками
- **Секции**: Каждая секция разбивается независимо
- **Метаданные**: Каждый чанк хранит заголовок статьи, секцию, категории

### Алгоритм поиска

Wiki search tool использует сопоставление ключевых слов:
1. Разбивает запрос на слова
2. Проверяет каждый чанк на наличие слов
3. Вычисляет оценку релевантности (совпадения / общее количество слов)
4. Возвращает топ результатов, отсортированных по оценке

### Хранение

- **SQLite**: Метаданные статей и текст чанков
- **FAISS**: Векторные embeddings для семантического поиска
- **Изоляция по мирам**: Каждый мир имеет свой RAG индекс
