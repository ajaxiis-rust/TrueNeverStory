# TrueNeverStory — Отчёт аудита безопасности

**Дата:** 2026-07-04  
**Версия:** 0.14.0  
**Область:** Полный обзор безопасности кодовой базы  

---

## Краткое резюме

TNS имеет **прочную основу безопасности** для своей модели угроз (локальный/однопользовательский AI-движок ролевой игры). Аутентификация, защита от SQL-инъекций, защита от инъекции промптов и санитизация входных данных хорошо реализованы. Основные риски связаны с крайними случаями: политика CSP, обход путей статических файлов, валидация аутентификации WebSocket и паттерны прототипного загрязнения через `Object.assign`. Большинство проблем имеют среднюю серьёзность для локального развёртывания, но были бы высокоприоритетными для публичного инстанса.

**Общая оценка: СРЕДНЯЯ** — адекватна для локального использования, требуется ужесточение для публичного развёртывания.

## 2. SQL-инъекции

### Сильные стороны

**Все SQLite-запросы используют параметризованные плейсхолдеры (`?`).** Нет интерполяции строк в SQL.

- `src/lib/sqlite-store.ts` — Все 30+ запросов используют плейсхолдеры `?`
- Запросы FTS5 санитизируются через `sanitizeFtsQuery()` на строке 990: удаляются не-словесные символы
- Запросы FTS5 MATCH строятся из санитизированных токенов, объединённых `OR`

### Проблемы

Не найдено. SQL-инъекции хорошо обработаны.

## 3. Межсайтовый скриптинг (XSS)

### Защита на фронтенде

| Контроль | Расположение | Статус |
|----------|-------------|--------|
| DOMPurify | `public/static/vendor/purify.min.js` | Доступен для санитизации HTML |
| CSP заголовок | `src/middleware/security-headers.ts:27-28` | Установлен, но слабый |

### Проблемы

| Серьёзность | Проблема | Расположение | Описание |
|-------------|----------|-------------|----------|
| **ВЫСОКАЯ** | CSP разрешает `unsafe-inline` | `security-headers.ts:27-28` | `script-src 'self' 'unsafe-inline'` разрешает выполнение инлайн-JavaScript. XSS-инъекция полностью обходит CSP. Следует использовать nonce-based или hash-based CSP. |
| **СРЕДНЯЯ** | CSP разрешает `unsafe-inline` для стилей | `security-headers.ts:28` | `style-src 'self' 'unsafe-inline'` — возможна CSS-инъекция. |
| **НИЗКАЯ** | Сообщение об ошибке на странице входа не санитизировано | `auth.ts:112` | `renderLoginPage(error)` интерполирует строку ошибки в HTML без экранирования. Сообщения об ошибках генерируются сервером (не пользовательский ввод), поэтому низкий риск, но defense-in-depth требует экранирования. |

## 4. Обход путей

### Проблемы

| Серьёзность | Проблема | Расположение | Описание |
|-------------|----------|-------------|----------|
| **СРЕДНЯЯ** | Раздача статических файлов без валидации пути | `src/app.ts:52` | `join(PUBLIC_DIR, c.req.path.replace(/^\//, ""))` — нет проверки, что разрешённый путь остаётся внутри PUBLIC_DIR. `join()` Hono может не предотвратить обход `..` на всех комбинациях ОС. |

| Серьёзность | Проблема | Расположение | Описание |
|-------------|----------|-------------|----------|
| **НИЗКАЯ** | `execSync` для скриптов установки | `src/routes/models.ts:71` | `execSync(\`bash "${scriptPath}"\`)` — scriptPath строится из имени из белого списка + фиксированной директории, поэтому не эксплуатируется напрямую. Но паттерн хрупок, если белый список будет расширен. |

### Небезопасные паттерны не найдены

- Нет использования `eval()` в продакшен-коде (только в тестах для верификации `safeEval`)
- Нет использования `new Function()`
- `exec` импортируется в `model-manager.ts:8`, но grep не нашёл фактических вызовов `exec()` — только `execSync` в routes/models.ts
- Использование `child_process` ограничено конкретными контролируемыми контекстами

| Заголовок | Значение | Статус |

- `Cross-Origin-Resource-Policy: same-origin`

## Рекомендации (по приоритету)

1. **Исправить CSP** — Заменить `unsafe-inline` на nonce-based или hash-based CSP. Это самое высокоимпактное улучшение безопасности.
2. **Валидировать WebSocket-сообщения** — Применить `sanitizeInput()` к содержимому WS-сообщений перед передачей в движок.
3. **Валидировать токены сессий WS** — Проверять валидность токена по хранилищу сессий, а не только по наличию куки.
4. **Добавить проверки обхода путей** — Для статических файлов: проверять `resolvedPath.startsWith(PUBLIC_DIR)`. Для маршрутов миров: валидировать параметр `name` по допустимым символам.
5. **Добавить `Strict-Transport-Security`** при развёртывании с HTTPS.
6. **Убрать захардкоженные пути** в `settings.ts:101` — сделать директории моделей настраиваемыми.
7. **Добавить валидацию входных данных** к маршрутам, принимающим JSON без схем Zod.
8. **Рассмотреть постоянные сессии** — сессии на SQLite переживут перезапуски.
